# Paper Figure Plan

This file lists the recommended figures for the M-HIBE range-query paper and
the SVG files generated by `scripts/generate_paper_figures.py`.

## Generated Figures

## Baseline Comparison Figures

These are the figures for comparing our scheme against pure accumulator and
PoneglyphDB-style baselines. They are generated by
`scripts/generate_baseline_comparison_figures.py` from
`data/baseline_comparison.csv`.

### Figure A: Baseline server proving time

- File: `output/figures/baseline_server_time.svg`
- Purpose: compare server proving time among pure ZK-Accumulator, PoneglyphDB,
  and our M-HIBE+ZK scheme.
- Style: serif font, thick axes, log-scale y-axis, hatched bars, matching the
  provided PDF figures.
- Current status: PoneglyphDB is marked N/A until its measured time is filled
  into `data/baseline_comparison.csv`.

### Figure B: Baseline client verification time

- File: `output/figures/baseline_client_time.svg`
- Purpose: compare client-side verification time across schemes.
- Current status: PoneglyphDB is marked N/A until its measured time is filled.

### Figure C: Baseline VO/proof size

- File: `output/figures/baseline_vo_size.svg`
- Purpose: compare verification object/proof size across schemes.
- Current status: PoneglyphDB is marked N/A until its VO size is filled.
- Note: our current VO size uses query-range keys + query-scoped empty keys +
  ZK proof size. It does not include global parent key material touched on the
  server.

## Ablation Figures

These are useful for explaining our implementation, but they are not the main
baseline-comparison figures.

### Figure 1: Server proving time breakdown

- File: `output/figures/fig_runtime_breakdown.svg`
- Purpose: show that the parallel version mainly reduces the M-HIBE delegation
  component, while ZK commitment becomes the dominant remaining cost.
- Data: serial 3D vs parallel 3D, stacked by prefix extraction, WKD-IBE
  delegation, ZK commitment, and ZK prover.
- Suggested section: Evaluation overview.

### Figure 2: Engine A speedup source

- File: `output/figures/fig_engine_a_speedup.svg`
- Purpose: isolate Engine A and make clear that prefix extraction barely
  changes, while WKD-IBE key delegation receives the real speedup.
- Data: prefix extraction, WKD-IBE delegation, Engine A total.
- Suggested section: M-HIBE completeness layer evaluation.

### Figure 3: Client verification time

- File: `output/figures/fig_client_verification.svg`
- Purpose: show client-side verification cost on a log scale, separating
  empty-key checking from the ZK verifier.
- Data: serial and parallel empty-key check times, ZK verifier time.
- Suggested section: Client overhead.
- Caveat: key checking is sampled at up to 64 keys in the current benchmark.

### Figure 4: Proof and key material size

- File: `output/figures/fig_key_material.svg`
- Purpose: show that the ZK proof is compact, while M-HIBE empty-key material
  dominates the payload.
- Data: query-range key material, global parent key material touched,
  query-scoped empty-key material, ZK proof size.
- Suggested section: Communication cost.

### Figure 5: Cover size and query-space composition

- File: `output/figures/fig_cover_composition.svg`
- Purpose: connect the geometric cover to the query grid: how many regions are
  touched/selected and how many empty points are covered.
- Data: query canonical keys, global empty parent regions, query-scoped empty
  keys, unique answer points, empty query points.
- Suggested section: Completeness cover analysis.

### Figure 6: Worker sensitivity

- File: `output/figures/fig_worker_sensitivity.svg`
- Purpose: show that worker oversubscription gives only a small client-check
  improvement and should not be considered the main speedup.
- Data: client empty-key check time for 20, 100, and 200 workers.
- Suggested section: Parallelization ablation or appendix.

## Figures To Add After More Experiments

### Dataset-size scalability

- Suggested file: `output/figures/fig_scalability_rows.svg`
- X-axis: number of TPC-H rows, e.g. 10K, 30K, 60K, 120K, 240K.
- Y-axis: server proving time and client verification time.
- Purpose: show how the approach scales with database size.
- Needed data: run serial/parallel benchmarks at several row limits.

### Query-selectivity sensitivity

- Suggested file: `output/figures/fig_query_selectivity.svg`
- X-axis: query selectivity or query volume.
- Y-axis: query-scoped empty keys, proving time, proof/key material size.
- Purpose: show dependence on query size and answer density.
- Needed data: vary date/discount/quantity ranges.

### Comparison with baselines

- Suggested file: `output/figures/fig_baseline_comparison.svg`
- X-axis: scheme name, e.g. pure accumulator, PoneglyphDB, serial M-HIBE,
  parallel M-HIBE.
- Y-axis: proving time, verification time, proof size.
- Purpose: main comparison figure.
- Needed data: baseline runs under clearly stated hardware/thread settings.

### Full-key audit overhead

- Suggested file: `output/figures/fig_full_key_audit.svg`
- X-axis: sampled check, full check.
- Y-axis: client verification time.
- Purpose: clarify the cost difference between the benchmark's 64-key sampled
  check and a full check over all returned empty keys.
- Needed data: implement/run full key-check mode.
