Description of the algorithm
Preliminaries
LetD denote the database. Each datum in D is denoted as ( kα, kβ, v), where kα, kβ are
two keys used for range queries and v is a vector representing other values associated with this
datum. We ignore v since it is not directly related to the 2D range query. Thus, each datum
now is considered as a point. Let P denote a point, and Pi(kαi, kβi)∈D denote the point whose
ﬁrst coordinate is kαi and the second coordinate is kβi,i∈ [1, n], where n is the total number of
points in D. For each dimension, we use an l-bit binary string to represent the corresponding
coordinate, thus a point will be represented by a 2 l-bit binary string. In each dimension, the range
is [0l, 2l− 1]. Assume the points in D are sorted in the ascendant order ﬁrst by 1 st-dimension
coordinate and then by 2 nd-dimension coordinate. In other words, we have Pi < Pj if kαi < kαj,
or (kαi = kαj)∩ (kβi < kβj).
Let x, y, z, a, b, kαi, kβi be binary strings to represent corresponding values from now on.
Let pref(x) be the set of nodes inTl such that z∈ pref(x) if and only if z is a preﬁx of x. Let
P R(x) be the set of points such that P R(x) ={Pi(kαi, kβi)∈D| x∈ pref(kαi), i∈ [1, n]}. Visually,
P R(x) means the set of points inD who fall within x|⊥ since their ﬁrst coordinates have the preﬁx
x. We redeﬁne the method GetRoots(l, [a, b],K[a,b]) of Esha’s work. First, we redeﬁne K[a,b].
LetK(I, x) be a function which takes an indicatorI which indicates the dimension and a binary
string x. I = 1 denotes the 1 st dimension and I = 2 denotes the 2 nd dimension. If I = 1, we
ignore x.K(1, x) actually denotes the set of 1 st coordinates{kαi}i∈[1,n] of points inD, i.e.K(1,⊥)
is the set of all non-empty leaf nodes in 1 st−Tl. If I = 2, the function takes P R(x) and the output
is a set of 2 nd coordinates{kβi} of points in P R(x). In fact, K(2, x) represents all non-empty leaf
nodes in 2 nd−Tl(x).ThenK(I, x)[a,b] means a subset of K(I, x) in which the coordinates also fall
within [a, b].
We now have GetRoots(l, [a, b],K(I, x)[a,b]) which runs the same as GetRoots(l, [a, b],K[a,b]).
It returns a set of nodes that represents the union of the canonical coverings of the empty ranges
according to the set of coordinates in K(I, x)[a,b].

For x = 001,

since we abort if Q(x) is⊥.
In fact, until now, we have described the whole story of the algorithm to generate commitments.
That is, ﬁrst take all ﬁrst coordinates and generate Commit(∗|⊥). Then for any x∈T l, generate
Commit(x|∗). Since if there is no point lie within x|⊥, it is not necessary to generate Commit(x|∗),
we can skip the commitment generation for those xs. Indeed, we can predict which x we should
skip before Step 2 by the result of Step 1. That is, if x is a suﬃx of nodes in R(returned by

pretation is that we only need to care x where there are some points whose ﬁrst coordinates have
the preﬁx x.
By the above description, we can also see the commitments generated by the algorithm is a
more eﬃcient version of the commitments of the trivial solution.

How to prove a region is empty
Assume the client asks to prove a region [xlo, xhi]×[ylo, yhi] is empty, where xlo, xhi, ylo, yhi are
l-bit binary strings representing the corresponding coordinate.
Assume{c1, c2, c3} is the canonical covering of the range [ xlo, xhi] ,where ci is a binary string,
i∈ [1, 3] and{d1, d2, d3} is the canonical covering of the range [ ylo, yhi], where di is a binary string,
i∈ [1, 3], the query for the proof should be{c1, c2, c3}×{d1, d2, d3}, i.e. c1|d1,c1|d2,c1|d3,c2|d1,c2|d2,c2|d3,
c3|d1,c3|d2,c3|d3.
In general, we make the following statement.
Statement: Given a region [ xlo, xhi]× [ylo, yhi], and C ={c1,··· , ci,··· , cs} is the canonical
covering of the range [ xlo, xhi], D ={d1,··· , dj,··· , dt} is the canonical covering of the range
[ylo, yhi], then the region can be represented by the union of {ci|dj} for all ci∈ C, dj ∈ D, i∈
[1, s], j∈ [1, t]. s, t are the number of nodes in the corresponding set, respectively.
Proof: We can split the region by 1 st-dimension coordinate and 2 nd-dimension coordinate.
Firstly, we split the region by 1 st-dimension coordinate. That is, the range of the 1 st-dimension
[xlo, xhi] can be represented by the union of {ci} where ci∈ C, i∈ [1, s]. Then, the region can
be represented by the union of the subregions [ ci0··· 0  
l−bit
, ci1··· 1  
l−bit
]× [ylo, yhi],i∈ [1, s]. Then, we
split each subregion by 2 nd dimension coordinate. The range [ ylo, yhi] can be represented by D =
{d1,··· , dj,··· , dt}. Thus, for each subregion, it can be divided to subsubregions [ci0··· 0, ci1··· 1]×
[dj0··· 0, dj1··· 1], which is ci|dj(where i∈ [1, s], j∈ [1, t]). Thus, we complete the proof.
To ask for a proof that the region [ xlo, xhi]× [ylo, yhi] is empty, ﬁrst the client will generate
canonical coverings of the ranges in each dimension, denoted as C and D, for each dimension
respectively. Then, the client combines each node ci∈ C with each canonical node dj ∈ D to
form the subregion ci|dj. The client asks for proofs for each subregion. The size of proof for each
rectangle will be O(l2).

.They are indeed the canonical coverings of the rectangles ci|[c, d].
Proof of Completeness of Commitments
The completeness of commitments means, for any query for a proof of p|q, where p, q are
binary strings, if the region represented by p|q is empty, we can ﬁnd a commitment commit(p′|q′)

to generate a proof for p|q, with 100% certainty. p′, q′ is the preﬁx of p, q respectively. Note that
⊥ is the preﬁx for any string.
We prove it by two steps. We assume the whole region [0 l, 2l− 1]× [0l, 2l− 1] is not empty,
which means there is no commit(⊥|⊥). If the whole region is empty, a commit(⊥|⊥) is suﬃcient
to generate all proofs.
Step 1
In this step, we prove that if we generate commitments on each node x (the trivial solution) of
the full binary tree 1 st−Tl, as Commit′(x|∗), we will deﬁnitely ﬁnd a commitment commit(p′|q′).
Statement: For any challenge on p|q, where p, q are binary strings, if the region p|q
is empty, then there must be a commitment commit(p|q′)∈ Commit′(p|∗) that q′ is the
preﬁx of q.
Proof: Let Q(p) be the output of GetRoots(l, [0l, 2l− 1],K(2, p)[0l,2l−1]), denoted as Q(p) =
{d1, d2,··· , di,··· , dt} is the canonical coverings of empty ranges based on the second coordinates
of points in D. Commit′(p|∗)={commit(p|d1),··· , commit(p|di),··· , commit(p|dt)}. By the def-
inition of canonical covering of the range, if the region p|q is empty, then there must be some
di = q′∈ Q(p), which is the preﬁx of q. That means commit(p|q′)∈ Commit′(p|∗).
Step 2
We will now show that the two types of commitments, i.e. Commit(x|∗), and Commit(∗|⊥)
is suﬃcient to generate all Commit′(x|∗) in the ﬁrst step, for all x in the full binary tree.
The proof is obvious. For x∈T l where there are no point inD falling in x|⊥, the commitment
commit(x|⊥) can be derived by a Commit(z|⊥) where z∈ GetRoots(l, [0l, 2l− 1],K(1, x)[0l,2l−1]),
since z is a node in the canonical covering of the empty ranges for ﬁrst coordinates. Thus, we can
use Commit(∗|⊥) type commitments to cover commit(x|⊥) where there are no point in D falling
in x|⊥. For x∈T l where there are at least one point falling within x|⊥, the Commit(x|∗) type
commitments which are exactly the same as the commitments in the trivial solution. Thus, the two
types of commitments Commit(x|∗), and Commit(∗|⊥) are suﬃcient to generate commitments as
in the trivial solution.
Complexity Analysis
There are two types of commitments. Commit(∗|⊥) and Commit(x|∗).
The number of commitments in Commit(∗|⊥) is O(nl), since there are O(n) diﬀerent empty
ranges and each range should be represented with O(l) nodes.
Now let us compute the number of commitments inCommit(x|∗)| with respect to x. If there are
m points falling within x|⊥, the number of nodes inGetRoots(l, [0l, 2l−1],K(2, x)[0l,2l−1]) are O(ml).
For each level of the treeTl, e.g. the ith level, for each node y in that level,|Commit(y|∗)| = O(myl)
where my means the number of points falling within y|⊥. In total, for all y in the i th layer, the sum
of commitments Commit(y|∗)y in ith level is O(nl) since each point can only show up in one region
once. That holds for each layer. In total, there are l + 1 layers, thus, the sum of Commit(x|∗) type
commitments are O(nl2).
In total, the complexity for storage of commitments is O(nl2)
Similarly, from the perspective of the client, the number of challenge they need to issue is
O(mD′l2) where mD′ is the number of points in the answer, since they ﬁnd O(mD′) rectangles and
each rectangles can be represented by O(l2).
