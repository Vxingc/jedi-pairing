2 MHIBE Construction with JEDI
In [1], the authors propose JEDI scheme where the encryption module works exactly as a two-
dimensional HIBE. In their construction, a message is encrypted with a two-dimensional “identity”.
Each dimension has a hierarchy. The ﬁrst dimension is used to represent Uniform Resource Indicator
(URI), which is like a ﬁle path. For example, a message m can be sent (in the encrypted form) to
the URIbuildingA/floor 2/roomLHall/sensor 0/temp. Anyone who has a secret key for the preﬁx
of this URI can derive a secret key for it to decrypt the message m. Another dimension is used to
express time, which is represented as year/month/day/hour. Similarly, anyone who has a secret
key for the preﬁx of a time representation can derive a secret key for this time presentation. For
example, a secret key for 2019/DEC/10 can be used to derive the secret key for 2019 /DEC/10/9.
In JEDI, the secret key is associated with both URI and time. To be consistent with MHIBE, we
can regard the secret key is associated with ( URI,time ) which can be seen as a two-dimensional
identity. The slashes in URI and time representation can be replaced by commas to transform the
representation to vectors. As in MHIBE, a secret key associated with the URI URI and the time
t (i.e.(URI,t )) can and only can derive the secret key associated with URI′ and t′ (i.e.(URI′,t′))
where URI is a preﬁx of URI′ and t is a preﬁx of t′.
With JEDI, we can directly extend their encryption scheme to support d-dimensional HIBE
where d ≥ 2. Indeed, the encryption scheme in JEDI is based on WKD-IBE [2] scheme, which
is also the core of the MHIBE construction. Thus, we ﬁrst explain WKD-IBE [2] scheme as a
preparation for our construction .
2.1 WKD-IBE scheme
In WKD-IBE scheme, messages are encrypted with patterns. We assume all patterns have a
ﬁxed length l. A pattern P with length l is a list of values: P = (Z∗
p ∪ {⊥})l, where ⊥ means a
wildcard. We denote P (i) as the ith component of P , 1-indexed. For consistency with MHIBE
construction, we regard P as a vector of l entries, where the ith entry corresponds to P (i).
Here, we denote the component containing Z∗
p as ﬁxed, and the component containing ⊥ as free.
A patternP2 matches a patternP1 if and only if: for all i ∈ [1,l ],P1(i) = ⊥ orP1(i) =P2(i). That
means, if the ith component is ﬁxed in P1, P2 must match it at the index i. If the ith component
is free (i.e. ⊥), whatever P2(i) is, it can match P1(i) since P1(i) is a wildcard.
A secret key associated with a pattern P1 can decrypt the message encrypted with a pattern
P2 if and only if P1 = P2. Furthermore, in WKD-IBE, a secret key associated with a pattern P1
can be used to the derive the secret key for a pattern P2 where P2 matchesP1. Thus, a secret key
associated with a pattern P1 can be used to decrypt any message encrypted with a pattern P2 if
P2 matchesP1.
The concept of ﬁxed and free can help the readers understand the process of deriving secret
keys from one pattern P1 to another pattern P2. We deﬁne them as follows.
Deﬁnition 1. For a pattern P , we deﬁne:
fixed(P ) = {(i,P (i))|P (i) ̸= ⊥}
free(P ) = {i|P (i) = ⊥}

2.2 Supporting Multiple Dimensions Using WKD-IBE
Recall that JEDI realizes a 2-dimensional HIBE scheme where the ﬁrst dimension represents
URI and the second dimension represents time. They achieve the 2-dimensional HIBE by using
WKD-IBE creatively. Speciﬁcally, assume the maximum length of URI is l1 and the maximum
length of a time representation is l2. JEDI sets the maximum length of a pattern to be l =l1 +l2.
A pattern P is associated with the URI and time ( P a vector) where the ﬁrst l1 entries represent
URI and the last l2 entries represent the time.
The message is encrypted with a pattern. Here, we explain how to represent URI and time as
patterns in encryption. If the length of the URI associated with m is shorter than l1, for example,
l1 = 5 and URI is a/b/c, the URI will be represented as a/b/c/$/⊥ where $ is a terminator symbol
and ⊥ means this entry is free. For the time, if the length of the time representation is shorter
than l2 = 4, such as 2019/DEC/, it will be represented as 2019 /DEC/ ⊥/⊥ which means the last
two entries are free. Thus, a message associated with a/b/c/ and 2019/DEC/ will be encrypted
with the pattern (a,b,c, $, ⊥, 2019,DEC, ⊥, ⊥).
Secret keys are also associated with patterns. If the length of URI or of time representation is
shorter than the maximum length, the remaining non-ﬁxed entries are automatically regarded as
⊥, which means they are free. For example, a secret key associated with a/b/c/ and 2019/DEC/
is equivalent that it is associated with the pattern ( a,b,c, ⊥, ⊥, 2019,DEC, ⊥, ⊥)
Thus, the URI and time can be combined to form a patternP2 as in WKD-IBE and the message
m can be encrypted with P2. A secret key associated with a pattern P1 can be used to derive a
secret key for the pattern P2 if and only if P2 matches P1. Since URI and time representation ﬁx
their representation slots from left to right, P2 matchesP1 also means the URI in P1 is a preﬁx of
the URI in P2 and the time in P1 is also a preﬁx of that of P2.
Note that adding a terminator symbol $ in URI in encryption is not necessary for security
purpose. Thus, we can omit $ and replace it with ⊥ in our construction.
2.3 MHIBE construction with JEDI

d ≥ 2. We let the maximum length of a pattern to be l = dlb where lb is the length of binary

scheme [3]).We explain our detailed construction which is based on the construction provided in
JEDI scheme [1], Appendix A.1.

we ﬁrst describe how to represent the d-dimensional identities as patterns.

2.4 Proof of security and the history-independence property
Our scheme is a direct application of JEDI [1] without modiﬁcation. For the history-independence
property, the proof is just as the proof in [1]. For the security, we will provide the proof in the
following.
To be noted, after reading the proof of security in JEDI scheme [1], I found their proof (Theorem
1 in [1]) was ﬂawed. The authors observe that the encryption algorithm in the original WKD-IBE
scheme in [2] which can only work with identities, can be extended to work with arbitrary patterns.
Thus, they construct their own WKD-IBE scheme on the basis of the original WKD-IBE scheme
using their observation. However, they did not provide a proof for their observation. In their
proof of security, they prove the security of their JEDI directly on the basis of their constructed
WKD-IBE rather than the original WKD-IBE scheme, which is not rigorous.
Our scheme is constructed on the basis of the WKD-IBE scheme in JEDI scheme [1]. However,
in the following proof, I will prove the security of our scheme directly on the basis of the original
WKD-IBE scheme in [2].
