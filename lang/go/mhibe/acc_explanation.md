# `acc.go` 解释文档

## 1. 文件定位

`acc.go` 是一个“纯 ZK-Accumulator 基线 benchmark”。它做两件事：

1. 证明返回结果 `I` 确实来自数据库 `DB`，也就是正确性。
2. 证明查询范围内剩余的空间确实为空，也就是完备性。

这份代码没有真正执行 M-HIBE 密钥派生，而是复用了“前缀覆盖 + 空区域提取”这一套空间切分逻辑，把空区域转成零知识非成员证明的输入。

## 2. 数据模型

- 空间维度固定为 3 维，`NumDims = 3`
- 每一维按 `BitLength = 12` 位编码
- `Point` 表示一个三维点
- `RangeQuery` 表示三维闭区间查询

实际映射关系是：

- 第 0 维：日期，按 `1992-01-01` 起的天数编码
- 第 1 维：折扣，读取 `cols[6]` 后乘以 `100`
- 第 2 维：数量，读取 `cols[4]`

因此，一个 TPC-H `lineitem` 元组会被映射成一个 36 位二进制点。

## 3. 核心辅助函数

### 3.1 `getCanonicalCover`

作用：把一维区间 `[min, max]` 映射成若干二叉前缀。

思路：

- 把整段定义域看成一棵满二叉树
- 如果当前节点区间被查询完全覆盖，直接返回当前前缀
- 如果完全不相交，返回空
- 否则递归左右子树

结果是一组“规范覆盖前缀”，它们互不重叠，合起来正好覆盖查询区间。

### 3.2 `MapToIDs`

作用：把三维范围查询映射成多维前缀标识。

步骤：

1. 对每个维度分别调用 `getCanonicalCover`
2. 对三维结果做笛卡尔积
3. 形成形如 `prefixX||prefixY||prefixZ` 的 ID

这些 ID 代表查询框在前缀空间中的分块。

### 3.3 `FormatToWildcardPattern`

作用：把每个维度的前缀补齐为长度固定的 12 位，用 `*` 表示未约束位。

例如：

- 前缀 `10||011||1`
- 会变成一个 36 位通配模式

这个通配模式代表一个超矩形子空间。

### 3.4 `FormatPointToBinary`

作用：把三维点编码成固定长度的 36 位二进制串，用于：

- 与通配模式做匹配
- 作为累加器元素的种子输入

### 3.5 `SubtractPointOrdered`

作用：从一个通配模式中减去一个真实点。

核心思想：

- 如果点不在模式里，模式原样保留
- 如果点在模式里，就按 `bitOrder` 指定的位顺序逐步“收紧”模式
- 每碰到一个 `*`，就生成一个与目标点该位相反的分支
- 这些相反分支就是“不包含该点的剩余空区域”

这相当于把“一个大块空间减去一个点”拆成若干个互不包含该点的更小块。

### 3.6 `SubtractPointsOrdered`

作用：把多个点依次从初始查询空间中扣除。

结果是：

- 输入：查询覆盖得到的初始模式集合
- 输出：扣除所有真实数据点后剩下的空区域模式集合

### 3.7 `ParseDate`

作用：把日期字符串转成相对 `1992-01-01` 的天数，保证日期维度可直接进入 12 位整数编码。

## 4. `main` 主流程

## 4.1 全局初始化

- 初始化 `bls12-381`
- 初始化 `bpacc.BpAcc`
- 从 `./pkvk-17` 加载累加器所需密钥

这里的累加器承担“真实性 / 正确性 / 非成员性”证明。

## 4.2 读取数据并构造三类集合

程序从固定文件读取数据：

- `/home/xing/poneglyphdb/src/data/lineitem_120K.tbl`

对每一行：

1. 解析数量、折扣、日期
2. 映射成三维点 `Point`
3. 把点编码成二进制串
4. 再通过 `bpacc.SeedToFr` 映射到有限域元素

随后把数据分成三份：

- `dbFr`：整个数据库的域元素集合
- `I`：命中查询的元素集合
- `X`：未命中查询的元素集合

这里的查询条件被写死为：

- 日期：`1994-01-01` 到 `1994-12-31`
- 折扣：`5` 到 `7`
- 数量：`0` 到 `23`

## 4.3 构造数据库承诺

代码对两组数据做承诺：

- `digest_DB`：整库承诺
- `digest_X`：查询补集承诺

后续零知识证明都围绕这两个承诺展开。

## 4.4 提取空区域

流程如下：

1. `MapToIDs(query)` 生成查询框的规范覆盖前缀
2. `FormatToWildcardPattern` 把它们变成通配模式
3. 用两种位顺序切分：
   - 以第 0 维为主
   - 以第 1 维为主
4. 把两种切分得到的空模式合并成 `combinedEmptyPatterns`

这里的目的不是返回真实结果，而是构造“查询空间中哪些区域没有数据”的可证明对象。

## 4.5 证明 A：命中结果的成员证明

这一部分证明 `I` 是合法查询结果的一部分。

步骤：

1. 用 `I` 构造多项式 `I_poly`
2. 对 `I_poly` 做 Pedersen 承诺，得到 `C_I`
3. 调用 `ZKMemProver(C_I, digest_X, ...)`
4. 再调用 `ZKDegCheckProver(...)` 证明承诺的次数正确
5. 客户端分别运行 `ZKMemVerifier` 和 `ZKDegCheckVerifier`

从逻辑上看，它想表达的是：

- 返回结果承诺中的元素与查询补集 `X` 不冲突
- 同时这个承诺对应的多项式结构是合法的

## 4.6 证明 B：空区域的非成员证明

这一部分证明“提取出的空区域里确实没有数据库真实点”。

步骤：

1. 把每个空模式字符串映射成域元素，形成 `emptySet`
2. 用 `ProveBatchNonMemFake(dbFr, emptySet)` 为整库相对 `emptySet` 生成批量非成员证明
3. 对 `emptySet` 的多项式做 Pedersen 承诺，得到 `CEmpty`
4. 运行 `ZKNonMemProver`
5. 再运行 `ZKDegCheckProver`
6. 客户端分别验证非成员证明和次数证明

这部分对应“完备性”：

- 查询区域内凡是不在结果集中的部分，应该都能被解释为真实空区域。

## 4.7 最终输出

最后输出三类指标：

- 空前缀提取时间
- 成员证明生成 / 验证时间与大小
- 非成员证明生成 / 验证时间与大小

最终布尔值：

- `Overall (completeness && correctness)`

只有成员证明和非成员证明都成功，才认为这次实验同时满足正确性与完备性。

## 5. 这份代码的本质

可以把 `acc.go` 理解成一个两层结构：

1. 上层是空间查询逻辑：把范围查询切成前缀块，再减去真实点，得到空块。
2. 下层是密码学证明逻辑：对命中结果和空块分别做零知识成员 / 非成员证明。

所以它更像一份“学术验证脚本”，而不是可直接部署的查询服务。

## 6. 阅读重点

如果你只想抓住主线，优先看这几个函数：

- `MapToIDs`
- `FormatToWildcardPattern`
- `SubtractPointOrdered`
- `SubtractPointsOrdered`
- `main`

前四个函数负责“把几何查询变成可证明对象”，`main` 负责“把这些对象送进累加器证明体系”。
